# CMS (Payload 3)

- Payload живет в том же приложении: админка `/admin`, REST `/api/*`, GraphQL выключен, интерфейс админки по-русски,
  редактор текста — lexical.
- `src/proxy.ts` пропускает `/admin` и `/api` мимо префикса языка, иначе `/admin` уезжал бы на `/ru/admin`
  (`tests/unit/proxy.test.ts`).
- База, миграции, генерация типов — в `CLAUDE.md`.

## Коллекции (`src/cms/collections/`)

- `cases` — название, адрес, демо или клиент, ниша из справочника квиза, направление, ссылка на демо, обложка
  (`media`, обязательна), задача и решение (textarea, абзацы разделяет пустая строка), технические результаты
  (`metrics`: значение и подпись), скрин Lighthouse (`media`, необязателен). Текстовые поля, включая значения и подписи
  метрик, локализованы. Черновики (`versions: { drafts: true }`), чтение — `publishedOrSignedIn`, как у `posts`.
  Миграция `cases_detail` переводит кейсы, заведенные до нее, в черновики (`_status` по умолчанию `draft`) без обложки:
  на сайте их нет, пока в админке не добавить обложку и не опубликовать.
- `posts` — черновики и публикация, текст в lexical.
- `team` — имя, роль в проекте, ядро или сеть, «в профессии с года» (из него B11 считает сумму лет).
- `media` — картинки режутся на `thumbnail`/`card`/`wide` в webp (`MEDIA_SIZES`); меньше размера не растягиваются.
- `users`; глобал `settings` (почта для связи).
- Текстовые поля локализованы ru/en, язык по умолчанию — русский, пустой английский отдается русским (`fallback: true`).

## Роли и доступ

- Роли `admin` и `editor` (`Role` в `src/cms/consts.ts`, правила доступа — `src/cms/access.ts`).
- Редактор ведет кейсы, посты, команду и медиатеку, видит только свою учетную запись; настройки, пользователей и роли
  меняет только администратор.
- Первый пользователь, заведенный формой админки, становится администратором (хук `firstUserIsAdmin`): поле роли правит
  только администратор, а его еще нет.
- Черновик поста или кейса без входа не отдается ни REST, ни Local API с `overrideAccess: false`.
- Почтового адаптера у Payload нет (на старте он пишет «No email adapter provided»): «Забыли пароль?» в админке письмо
  не шлет, ссылка сброса уходит в лог сервера → пароль сбрасывает администратор. Адаптер подключать вместе с исходящей
  почтой сервера — сейчас SMTP закрыт хостингом.

## Чтение на страницах

- Страницы читают CMS функциями из `src/cms/` (`getCases`, `hasCases`, `getCaseBySlug`) с `overrideAccess: false` — фронт видит ровно то, что видел бы
  анонимный REST.
- Картинки кейса приходят как `CaseImage`: адрес, подпись из медиатеки, размеры и готовый `srcSet` из нарезанных
  `MEDIA_SIZES`; на странице — обычный `<img>` (`src/components/CaseImage.tsx`), не next/image.
- Кеша нет: страницы и так рендерятся на каждый запрос (layout читает cookie направления и темы), правка в админке видна
  со следующей загрузки. Добавишь кеш → добавь и сброс по `afterChange`.

## Заголовки `withPayload`

- `withPayload` вешает на все адреса подсказку клиента о теме (`Accept-CH`, `Critical-CH: Sec-CH-Prefers-Color-Scheme`),
  а на странице сайта Chrome из-за `Critical-CH` при первом визите повторяет запрос документа.
- `next.config.ts` сужает это правило до `/admin/:path*`; `tests/e2e/headers.spec.ts` держит страницы сайта без этих
  заголовков. Проверка после обновления Payload — в `CLAUDE.md`.
